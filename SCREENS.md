# Screen Inventory — PAYGO

## Shell screens
### S-01 Splash / Loading
Purpose:
- initialise app
- init Firebase
- establish anonymous session

### S-02 Region Selector
Purpose:
- choose market context
- set brand theme basis

### S-03 Customer Selector
Purpose:
- choose persona within selected region

### S-04 Config Panel
Purpose:
- manipulate demo state and scenario presets
- likely Phase 5, not day-one requirement

## Consumer screens
### A-01 Home / Dashboard
Always core. Must be believable and feature-composed.

### A-02 Manual Top-Up
Initial must-have payment action.

### A-03 Scheduled Top-Up
Important early extension for credible prepaid variety.

### A-04 Auto Top-Up
Important for standard and convenience narratives.

### A-05 Rules Builder
Defer unless needed for a specific stakeholder narrative.

### A-06 Balance Management
Defer unless passive management model becomes a key talking point.

### A-07 Usage Graph
Strong demo value once daily usage data is wired.

### A-08 Real-Time Usage
High-impact smart demo item.

### A-09 TOU Pricing
Important for US smart/EV stories.

### A-10 Payment History
Must-have credibility screen.

### A-11 Spend Summary
Nice-to-have after core money flows.

### A-12 Emergency Credit
Important for vulnerable/debt narratives.

### A-13 Debt Repayment
Useful for debt-risk storylines.

### A-14 Meter Read Submission
Important for IE/non-smart realism.

### A-15 Notifications
Useful but can stay light initially.

### A-16 EV Scheduler
Later smart/ecosystem feature.

### A-17 Solar Export
Later advanced persona feature.

### A-18 Battery Widget
Later advanced persona feature.

### A-19 Support / Help
Always shown.

### A-20 Account Settings
Always shown. Includes demo reset.

## First-build recommendation
Build in this order:
1. splash
2. region selector
3. customer selector
4. dashboard
5. manual top-up
6. payment history
7. support/account shell
8. scheduled and auto top-up
9. emergency credit
10. config panel
